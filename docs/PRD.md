## 1. 프로젝트 개요

### 1.1 배경
2025년 방한 일본인 관광객은 역대 최고치인 약 365만 명을 기록했으며, 이는 일본 전체 출국자의 24.8%에 해당한다. 한국(부산)은 일본인에게 가장 인기 있는 근거리 여행지 중 하나로 자리 잡았지만, 실제 여행 결정 단계에서는 다음과 같은 명확한 기피 요인(Pain Point)이 존재한다.

| 기피 요인 | 비율 |
|---|---|
| 부담스러운 여행 비용 | 36.5% |
| 가계 소득 감소 | 26.5% |
| 엔저 현상 | 21.2% |
| 언어 장벽 | 19.1% |
| 출입국 절차의 번거로움 | 17.7% |

→ **경제적 부담**과 **언어·절차에 대한 심리적 불안**이 핵심 장벽이며, 본 서비스는 이 두 가지를 해소하는 데 집중한다.

### 1.2 목적
일본인 관광객에게 부산을 **가성비 높고 심리적으로 안전한 여행지**로 어필하는 일본어 기반 관광 지원 웹 서비스를 제공한다.

### 1.3 목표
- 언어 장벽 없이 이용 가능한 완전한 일본어 현지화 UX 제공
- 유명 관광지 중심이 아닌 **일본인 선호도가 높은 지역 중심 콘텐츠**로 차별화
- 별도 백엔드 서버 없이 Supabase 기반 서버리스 아키텍처로 빠르게 구현·운영

| 구분 | 내용 |

| 여행 성향 | 대만 등에서 경험한 '소도시 힐링' 여행을 선호, 유명 관광지보다 로컬 체험 선호 |

| 기기 환경 | 모바일 중심 (여행 중 실시간 검색), 반응형 웹 필수 |

## 3. 핵심 기능 (Features)

### 3.1 일본어 기반 지도 서비스 (Core)
- 네이버 지도 API 연동, 관광지/맛집/숙박 등 주요 스팟에 일본어 번역 정보 제공
- 카테고리별(관광지/맛집/숙소/체험) 필터링
- 현재 위치 기반 주변 추천 (Geolocation API)

### 3.2 맞춤형 관광지·맛집 추천
- 한국관광공사(TourAPI) 데이터를 활용한 관광지/음식점 정보 수집 및 일본어 큐레이션

### 3.3 선호도 높은 지역 콘텐츠
- 일본인 관광객 선호도가 높은 지역/스팟 소개 페이지
- 선호도 기반 랭킹·큐레이션 콘텐츠 제공

### 3.4 고효율 여행 동선 제안
- 예산·일정 기반 추천 코스(1일/2일 등) 제공
- 저비용 고효율 동선을 시각적으로 지도에 표시

### 3.5 행사·축제 정보
- TourAPI 행사정보(`searchFestival1`)를 활용한 부산 지역 축제/공연/이벤트 캘린더 제공
- 기간 중(진행 중/예정) 필터로 여행 일정에 맞는 행사 노출
- 지도·코스 추천과 연계하여 "여행 기간에 열리는 행사"를 자동 매칭

## 4. 기술 스택 및 아키텍처

### 4.1 기술 스택
| 영역 | 기술 |
|---|---|
| Frontend | HTML, CSS, JavaScript (Vanilla or 경량 프레임워크) |
| 지도 | 네이버 지도 API (Naver Maps JavaScript API) |
| 관광 데이터 | 한국관광공사 TourAPI - **일문 관광정보서비스_GW** (Open API, 일본어 관광지/숙박/음식점 정보 14종), 국문 서비스로 데이터 보완 |
| 데이터베이스/인증 | Supabase (PostgreSQL, Auth, Storage) |
| 배포 | 정적 호스팅 (Vercel/Netlify/GitHub Pages 등) — **백엔드 서버 없음** |
| 형상관리 | GitHub (브랜치 전략, PR 기반 코드 리뷰) |

### 4.2 아키텍처 개요
- **서버리스(Serverless) 구조**: 별도 WAS 없이 정적 프론트엔드가 Supabase 및 외부 API(네이버 지도, TourAPI)와 직접 통신
- Supabase Client SDK를 통해 인증(Auth), 데이터 CRUD(PostgreSQL), 파일 저장(Storage) 처리
- 한국관광공사 API 데이터는 배치성으로 수집 후 Supabase에 적재하거나, 클라이언트에서 직접 호출 후 캐싱하여 사용 (API Key 노출 방지를 위한 프록시 필요 시 Supabase Edge Function 활용 검토)
- 일본어 번역 데이터는 사전 가공하여 Supabase 테이블에 저장 (실시간 번역 API 의존도 최소화)

**TourAPI 활용 방식**
- **일문 관광정보서비스_GW**를 1순위로 조회, 데이터 누락 항목은 국문 관광정보서비스_GW로 보완 (일문 데이터는 국문 대비 커버리지가 낮음)
- 주요 엔드포인트: `areaCode1`(지역코드) · `categoryCode1`(분류코드) · `areaBasedList1`(부산 지역 관광지/맛집/숙소 목록) · `locationBasedList1`(좌표 기반 주변 추천 — 네이버 지도 연동 핵심) · `searchKeyword1`(키워드 검색) · `searchFestival1`(행사정보) · `searchStay1`(숙박정보) · `detailCommon1/detailIntro1/detailInfo1/detailImage1`(상세정보 4종)
- 공공데이터포털(data.go.kr) 또는 관광공사 콘텐츠랩(api.visitkorea.or.kr)에서 인증키 발급

> ⚠️ **주의**: 네이버 지도 API, TourAPI 키를 프론트엔드에 직접 노출할 경우 보안 이슈가 발생할 수 있으므로, 필요 시 Supabase Edge Functions(서버리스 함수)를 프록시로 활용하는 것을 권장한다. (완전한 '백엔드 없음'은 아니지만 별도 서버 운영 없이 구현 가능)

### 4.3 데이터베이스 설계 (Supabase / PostgreSQL) - 예시
| 테이블 | 주요 컬럼 |
|---|---|
| `spots` | id, name_ko, name_ja, category, lat, lng, description_ja, image_url, region |
| `preferred_areas` | id, area_name, area_name_ja, description_ja, preference_score |
| `courses` | id, title_ja, budget_level, spot_ids[], duration |
| `festivals` | id, title_ja, description_ja, area, start_date, end_date, image_url, spot_id |

## 5. UX/UI 요구사항
- 일본인 사용자 대상 **자연스러운 일본어 현지화** (기계 번역 티가 나지 않는 수준)
- 처음 방문하는 외국인도 직관적으로 이해 가능한 심플한 정보 구조 (아이콘 중심 내비게이션)
- 모바일 퍼스트 반응형 디자인 (여행 중 실사용 고려)
- 심리적 안정감을 주는 톤앤매너 (따뜻하고 친절한 안내형 UI 카피)
- 지도 중심의 시각적 정보 전달, 텍스트 의존도 최소화

## 8. 화면 구성 (IA) 및 필터 요구사항

### 8.1 사이트맵
```
홈 (지도 중심)
├─ 카테고리 상세 페이지 (관광지/맛집/숙박/체험)
│   └─ 스팟 상세 페이지
├─ 지역(선호 지역) 상세 페이지
│   └─ 스팟 상세 페이지
├─ 행사·축제 페이지
│   └─ 행사 상세 페이지
├─ 코스 상세 페이지 (추천 동선)
└─ 하단 탭: 홈 / 지도 / 행사·축제 / 코스
```

### 8.2 페이지별 요구사항
| 페이지 | 주요 구성 | 필터/정렬 |
|---|---|---|
| 홈 | 지도, 카테고리 진입, 선호 지역 카드, 추천 코스 배너, 행사·축제 배너 | - |
| 카테고리 상세 | 리스트/지도 토글, 스팟 카드(썸네일·이름·태그) | 지역(구/군), 세부 분류, 거리순/인기순 정렬 |
| 지역 상세 | 지역 소개, 대표 이미지, 소속 스팟 리스트 | 카테고리(관광지/맛집/숙박), 정렬(추천순/거리순) |
| 행사·축제 | 캘린더 뷰 또는 리스트, 행사 카드(기간·장소) | 진행상태(진행중/예정/종료), 기간(월별), 지역 |
| 행사 상세 | 행사 정보, 기간, 위치 지도, 관련 스팟 | - |
| 코스 상세 | 코스 개요, 동선 지도, 스팟 순서 리스트 | 예산대, 소요일수 |

### 8.3 공통 필터 UI 원칙
- 상단 가로 스크롤형 필터 칩(Chip) 사용, 다중 선택 가능한 항목은 명확히 구분
- 필터 적용 시 결과 개수 실시간 표시로 안심감 제공
- 필터 상태는 URL 쿼리 또는 세션 상태로 유지 (뒤로가기 시 유지)

## 9. 리스크 및 제약사항
- 네이버 지도 API, TourAPI의 일본어 데이터 부재 시 수동 번역/가공 리소스 필요
- 완전 무백엔드 구조에서 외부 API 키 노출 리스크 → Supabase Edge Function 프록시 검토 필요
- 한국관광공사 데이터의 최신성/정확성에 의존적
- 행사·축제 데이터는 TourAPI 갱신 주기에 의존적이므로 최신성 검증 로직 필요

## 10. 향후 로드맵 (제안)
1. **MVP**: 지도 기반 관광지 검색 + 선호도 높은 지역 콘텐츠 + 카테고리/지역 상세 페이지
2. **v2**: 행사·축제 페이지, 예산 기반 맞춤 코스 추천 고도화
3. **v3**: 다국어 확장 (영어/중국어)
